# GTNH 额外MOD管理工具

核心功能使用 Python 标准库实现；Wiki 的快速请求与浏览器验证使用可选依赖。
同时管理**客户端**与**服务端**的 mods 文件夹：安装、一键检查更新、更新（自动备份旧版本）、
启用/禁用开关，并区分客户端/服务端/双端 mod。

数据来源：[GTNH wiki - 可添加MOD](https://gtnh.huijiwiki.com/wiki/可添加MOD)（以 wiki 实时数据为准，
按网站分类：星门规则下的功能增强/性能优化/视听增强/旧版本限定 + 非星门规则）。
wiki 没有的 mod 可通过**自定义源**（GitHub 仓库 / 本地文件夹 / 手动登记）扩展。

## 运行

- 双击 `run_cli.bat` → 命令行交互菜单
- 双击 `run_gui.bat` → 图形界面
- 或命令行：`py -m gtnhmod cli` / `py -m gtnhmod gui`

要求：Windows + Python 3.10+（安装时勾选 py 启动器）。基础功能不需要 pip 安装额外包。

### 免安装版（exe）

不想装 Python 可直接到 [Releases](https://github.com/peco331/gtnh-extra-mod-manager/releases)
下载 `GTNHModManager-<版本>-win64.zip`：解压后 `GTNHModManager.exe` 是图形界面、
`gtnh-cli.exe` 是命令行（参数同下）。数据目录在 exe 旁的 `data/`
（可用环境变量 `GTNHMOD_DATA_DIR` 指到别处）。push tag `v*` 时 CI 自动构建发布；
本地打包：`scripts\build_exe.bat`（需 `py -m pip install pyinstaller curl_cffi websocket-client`）。

推荐（可选）：`py -m pip install --user curl_cffi websocket-client`。wiki 站开启 Cloudflare
人机验证后，程序先尝试模拟浏览器指纹直连；如果仍需要验证，会自动打开应用专用的
Edge/Chrome 窗口，用户完成验证后程序从同一浏览器会话读取 Wiki 原文。验证窗口关闭后才
会报告刷新失败；不会读取本地缓存充当本次刷新结果。已保存的目录仍可离线浏览。

非交互模式（可配合 Windows 任务计划每日自动检查）：

```
py -m gtnhmod cli --check        # 只检查并打印结果（有出错项时退出码为 1）
py -m gtnhmod cli --update-all   # 直接更新全部可更新的mod（有失败项时退出码为 1）
```

## 使用流程

1. **设置**（菜单 10 / 设置页）：填客户端、服务端 mods 文件夹路径（以后换目录随时改）；
   可选填 GitHub Token（提高 API 限额）。
2. **刷新Wiki数据**（菜单 1）：每次从 Wiki 网站重新请求并验证可添加 mod 列表；失败时
   明确报错，绝不拿旧缓存充当新结果。上次成功的目录保存在 `data/mods_db.json`，供离线浏览。
3. **可添加MOD列表**（菜单 2）：按网站分类浏览，查看详情（含 wiki 原文的 GTNH 版本兼容
   说明），**安装时按端别标注自动选择安装位置**（客户端/服务端/双端，目录未设置会提示
   跳过），支持多选批量安装。安装/更新时可**选择版本**。默认包含 Pre-release/Beta，
   在当前绑定源中先筛选 GTNH / Minecraft 1.7.10 构建，再按发布时间选择最新发布。
   **其他 Minecraft 版本、Fabric/NeoForge 文件会被排除**，同一 Release 多平台资产分别筛选。
   Wiki 与发布说明的兼容描述只作参考，不改变默认版本。缺少游戏平台标识的源需先核实，
   在 GUI 列表右键「确认此源用于 GTNH…」或 CLI 详情的「确认/撤销 GTNH 下载源」确认；
   明确的平台冲突不能由确认覆盖，重新绑定仓库后需重新确认。
   详情弹窗可查看更新日志；可右键**编辑中文名**（无中文名的 mod
   可自填）；wiki 链接标签带"推荐/特供"等字样的（如"OO修复版(推荐使用该版)"、
   "GTNH特供版"）自动作为默认下载源。
4. **检查更新 / 更新MOD**（菜单 4/5）：只查已安装、启用且未锁定的 mod（规避 GitHub 匿名
   API 60 次/时限额）；更新前旧 jar 自动备份到 `data/backup/{端别}/{mod}/`，更新失败
   不中断。更新（含多选）会先展示统一计划，一次确认后使用最新的合格发布；单个 mod 失败
   不影响其他。计划停留超过 5 分钟会重新检查并要求再次确认。**全部更新**只更新确实有新版可用的 mod。
5. **启用/禁用**（菜单 6，或菜单 3 选中后操作）：`xxx.jar` ↔ `xxx.jar.disabled` 重命名，
   客户端/服务端独立开关，重启游戏/服务端生效。
6. **未受管MOD**（菜单 7）：mods 目录里没被识别的 jar（含 GTNH 核心 mod）会列在这里，
   可关联到已有条目 / 注册为自定义 mod / 忽略，支持搜索框过滤。核心 mod 请勿乱动。
7. **已安装MOD**（菜单 3）一个 mod 一行，安装端别分三类（双端 / 仅客户端 / 仅服务端）；
   整合包自带等不想管的 mod 可「从列表剔除」（不删文件，菜单 10 可恢复显示）。
   可添加列表里已安装的 mod 有 `[已装:端别]` / 绿色 ✓ 标记。
8. **设置里的 GTNH整合包版本**：填写后（如 `2.9.0-beta1`），安装/更新选版本时会按
   Wiki/发布说明显示兼容提示；不填写也不影响选版。mods 目录与数据目录可在不同磁盘（跨盘复制自动处理）。

## 操作便捷性（GUI）

- **右键菜单**：所有列表（已安装/可添加/未受管/自定义源）右键弹出对应操作，
  双击已安装行可在**资源管理器中定位文件**（`explorer /select`）。
- **选择下载源**：wiki 上有些 mod 有多个下载链接（如 WorldEdit 有 GTNH 特供版和原版
  仓库），可添加列表右键「选择下载源...」（CLI 详情菜单「绑定下载源」）选择其一，
  检查更新/自动下载将使用该链接；绑定会记住并在刷新 wiki 后保留，详情页显示当前绑定。
- **删除mod**：已安装页按钮/右键可删除（jar 移入 `data/backup` 加 `.deleted` 后缀，
  可手动恢复）；CLI 菜单 3 也有删除。
- 过滤：已安装页「仅可更新」、可添加页「仅未安装」；版本选择器支持**双击/回车确认**；
  底部状态栏显示两端目录与已装数量；「打开mods目录」按钮直达文件夹。

## 端别规则（来自 wiki）

- 星门规则·功能增强/性能优化/视听增强/旧版本限定：按 wiki「运行环境」字段标注
  （多数是客户端专用，双端约 13 个；带「？」的标注为不确定）。
- 非星门规则模组：wiki 未标注 → 默认按**双端**处理（与整合包惯例一致）。
- 自定义源：添加时自己选择端别。
- 把 client-only 的 mod 装到服务端（或反之）时工具会给出黄色警告。

## 自定义源（菜单 8）

| 类型 | 用途 | 检查更新方式 |
|---|---|---|
| GitHub 仓库 | 填写 owner/repo（或粘贴仓库链接） | GitHub API 筛选 GTNH Release，含测试版（无 Release 时受限回退 tags） |
| 本地文件夹 | 朋友分享的 mod 目录、自收集目录 | 目录内可解析版本的最新 jar |
| 手动维护 | 只登记名字，跟踪状态 | 无上游；替换文件后重新扫描即识别新版本 |

## 数据与文件位置

默认全部在工具目录 `data/` 下（工具可整体拷贝/移动；不可写时自动回退
`%APPDATA%\GTNHModManager`，可用环境变量 `GTNHMOD_DATA_DIR` 覆盖）：

- `config.json` — 两端路径、token、代理、备份保留数等（可手改）
- `mods_db.json` — wiki 解析结果 + 自定义源（刷新 wiki 时自动合并，你手动关联的
  jar 名映射/自定义源不会丢）
- `installed.json` — 已装状态（版本、锁定、检查时间；不存路径，路径变了只需重设）
- `cache/` — GitHub API 条件请求缓存（ETag/304，6 小时新鲜度，限流友好）
- `backup/` — 更新前旧版本备份（菜单 9 可恢复）
- `logs/operations.log` — **操作日志**：安装/更新/恢复备份/启用禁用/锁定/剔除/注册等
  全部落盘记录（超过 2MB 自动轮转为 .old）；CLI 菜单 10 / GUI 设置页有"打开操作日志"入口

## Wiki 反爬（Cloudflare）

wiki 站开启 Cloudflare 人机验证后，程序直连会收到"请稍候…"验证页或 403。处理顺序为：

1. **快速通道**：安装 `curl_cffi` 后模拟浏览器 TLS 指纹请求。
2. **人工验证窗口**：检测到验证页或 403 时自动打开隔离的 Edge/Chrome 窗口；完成验证后，
   程序通过同一会话读取 raw Wiki 内容。浏览器会话保存在 `data/cache/browser_profile/`，
   不读取现有浏览器的 Cookie 数据库。
3. **失败时保留旧目录**：浏览器验证失败或网络不可用时明确报错，不合并旧缓存，
   不更新时间；已保存的目录保持可浏览。解析结果为空时也直接中止合并。

高级兼容入口仍可在设置页导入浏览器 Cookie（cf_clearance + 配套 UA），但普通刷新不需要
手工复制 Cookie。

## GTNH 发布筛选边界

- “适用于 GTNH 的游戏平台/构建”是硬性筛选；发布说明推断的整合包小版本兼容性只是提示。
- Mod 自身版本号不等于 Minecraft 版本号。无明确标识时要求确认下载源，不仅凭仓库名称放行。
- 查询最多 150 条 Release；达到范围上限会明确报告无法确认最新版本，不误报“已最新”。
- 发布时间不完整时按上游顺序显示并给出提示；最新 GTNH 发布没有 jar 时提示手动处理。
- 自动更新不降级。最新发布对应更低版本号时，需要手动选择确认。
- 下载后静态检查 jar 元数据，明确的游戏版本/加载器冲突在备份替换前拒绝。
  缺失元数据不等于冲突；这些检查不能代替实际游戏兼容测试。

## 已知限制与风险提示

- **CurseForge 源的 mod 无法自动下载**（CurseForge 下载 API 需要官方 key）。
  工具会打开浏览器页面，手动下载放入 mods 目录后重新扫描即可识别新版本。
- **GitHub 匿名 API 限额 60 次/时**：工具只查已装 mod + 条件缓存，通常够用；
  剩 10 次以内会提示，建议在设置中配置 GitHub Token（`github.com/settings/tokens`，
  只需公开仓库读取权限）。
- **版本比较**：支持 GTNH 常见格式（`5.09.44.03`、`0.2.0p05`、`2.0.0-GTNH`、
  `v0.8.0`、`1.0.0-beta1`）；无法解析的显示"请手动判断"，绝不静默替换。
- **jar 识别**：以 `1.7.10` 等 MC 版本为锚点切分"名字|MC版本|mod版本"，
  名字含连字符、版本带构建后缀（`GTNHModify_CutCorners-v1.3.17+2.9.0-beta-1`）都能切对；
  匹配只用英文名与别名（中文名里的拉丁残片如"NEI"会误配，已排除），
  前缀/缩写匹配有最短长度限制；检查更新/安装/更新时会自动从下载资产文件名
  学习真实 jar 命名（存入别名），以后扫描精确匹配。
- **更新时请关闭游戏/服务端**，文件被占用会明确报错（已下载的新文件会留在缓存，不丢失）。
- 每个 mod 自动保留 N 份旧版本备份（默认 3，可改），可随时恢复（菜单 9）。
- wiki 页面改版时：未知章节会被归入"非星门规则"并在刷新时提示警告；详情原文保留展示。

## 开发与测试

```
py -m unittest discover -s tests -v    # 单元/E2E/GUI 回归测试（离线，含真实wiki样例解析）
```

结构：核心库 `gtnhmod/`（versions/wiki/net/sources/scanner/downloader/updater...）
不依赖任何界面；`cli.py`（交互菜单）与 `gui.py`（Tkinter）是两个壳，
交互统一走 `ui.py` 的 UIProtocol（可测试）。

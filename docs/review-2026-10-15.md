# 1.6.7–1.6.9 审查与修复记录

本轮由 WTCT 安装失败触发，对 MOD、资源包/光影、配置、CLI/GUI、网络请求、扫描、更新计划、文件替换和恢复链路进行审查。修复以复现、隔离测试和真实上游验收为依据，不将测试通过等同于游戏内兼容。

## 已修复的问题

| 范围 | 问题及修复后的行为 |
| --- | --- |
| GitHub 设置 | 测试输入框 Token 与实际保存配置分离，造成“测试成功但安装匿名限流”。增加“保存并测试 GitHub API”，独立提交网络配置；保留“仅测试当前输入”并明确提醒未保存。 |
| 配额测试 | 配额为零仍显示成功。现在明确显示“配额已耗尽”。 |
| 配置提交 | 保存失败后内存配置可能先行生效。失败时恢复原配置，不刷新为已保存状态；后台任务期间不允许中途更改配置。 |
| 数字设置 | 缓存零值被默认值覆盖；NaN、无限值、负数和非法代理端口可被保存。零缓存可生效，非法值在保存前拒绝，备份至少保留一份。 |
| WTCT 标签 | `1.0.63-rc1`、`1.0.49-rc1`、`1.0.25-rc1` 被误拆为 Minecraft 前缀，随后被丢弃。仅剥离有依据的 MC 前缀，保留 MOD 预发布版本。 |
| 已安装版本 | 文件名也使用过宽的 MC 锚点，可能将 `wtct-1.0.63-rc1.jar` 的版本识别成 `rc1`。与发布解析一致地保留完整版本；修复已知 MC 数字碰巧作为 MOD 版本时的预发布比较。 |
| 下载资产 | 中间产物 `predowngrade` 与开发/源码附件不参与运行 JAR 选择。等分的多个运行 JAR 不再自动猜测；GUI/CLI 交互选版支持明确选择具体文件，自动流程转人工处理。 |
| 过期缓存 | MOD、GitHub 包和 Modrinth 包查询失败后的过期缓存不用于证明最新版本。格式异常也作为查询失败显示。 |
| 双端计划 | 原计划只比较其中一端。现在分别比较各端版本，将已最新、可更新、无法比较和降级分组；两端复用一次查询。 |
| 自动更新 | 未知本地版本转人工选版；执行计划时重新比较当前本地状态，不以显式目标版本绕过自动降级保护；禁用/锁定状态也在执行时检查。 |
| 检查与执行（1.6.9） | GUI 检查一次后保存资产、端别和相关文件状态。“全部更新”与“更新选中”只消费本次可自动更新的结果，不重新查询上游或发现新项目。结果超过 5 分钟或相关状态改变时，要求显式重新检查；确认前再次校验。 |
| 检查结果展示（1.6.9） | 最新一轮的查询失败、需人工处理、无法比较和本地较新状态覆盖旧缓存显示，避免失败条目仍表现为可自动更新。未完成本次检查时，全部更新按钮不可用；完成后显示可更新 MOD 数量。 |
| 状态显示 | 本地版本高于上游不再显示“已最新”。无自动下载资产不计为可自动更新，摘要分别显示需手动、无法比较与查询失败。 |
| 查询并发 | 更新计划的工作线程只查询，别名及发布时间写入在汇总阶段处理，避免并发查询线程反复修改数据库。 |
| 安装记录合并 | 本进程某端为空时，磁盘上的新安装记录原先会合并进临时空字典而丢失。现在合并进实际存储的字典。 |
| 文件匹配 | 多条等价别名/前缀匹配不再按列表或 ID 顺序猜测归属。自动清理冗余 JAR 时保留仅通过前缀/缩写推测关联的文件。 |
| 扫描失败 | 严格扫描失败不作为空目录清理 MOD 安装记录；包目录读取失败保留其安装记录。 |
| 替换保护 | 拒绝 Windows 设备名、数据流和越界/链接目标。目标文件已经存在且不是本次替换的旧文件时，先要求核对，避免覆盖另一份文件。失败时清理本次暂存文件。 |
| MOD 恢复 | 恢复 `.jar.disabled` 时保留禁用状态并正确记录版本。双端回滚先创建独立快照，防止首端备份轮换使次端失去恢复源。 |
| 删除恢复 | 同秒重复删除使用唯一备份名，保留两次删除的内容；替换备份按创建时更新备份时间，避免源文件旧时间影响轮换。 |
| 包校验 | ZIP 除结构检查外校验 CRC；资产声明大小不符时拒绝替换。 |
| 包恢复 | 先复制到暂存位置并备份当前内容，再原子恢复；复制失败不会先删除当前文件。恢复碰撞备份时还原原文件名。 |
| 包替换结果 | 新包已安装但旧文件移除失败时，记录新包并报告旧文件残留，避免把已经落盘的结果全部丢失。 |
| 来源绑定 | 包重新绑定来源时清除旧资产筛选；绑定仅在最新发布中匹配，不能以旧发布假装绑定仍有效。组织页不能猜测同名仓库。GitHub URL 按真实主机解析并处理 `.git` 后缀。 |
| 批量包操作 | 单条来源查询或资产筛选失败不取消其余条目。 |
| Wiki 名称与身份（1.6.8） | 链接目标、显示标记与引用不参与新 ID 生成。对已产生的新旧重复记录，以可读名称和项目地址共同确认身份，保留旧 ID 并登记历史 ID；合并别名、中文名覆盖与下载源绑定，迁移两端安装缓存与锁定。有来源/资产过滤冲突或多个候选时不猜测合并。 |
| 安装状态（1.6.8） | 可添加列表与磁盘注册表统一使用修复后的目录，避免已安装条目显示未安装，以及刚安装的扭曲空间科技、可编程仓室因重复别名而进入未受管列表。F5 与切换页签重新扫描，搜索继续复用本次扫描。 |
| 历史恢复（1.6.8） | 历史 ID 下的备份仍可选择和一键回滚，恢复后写入统一的安装记录；目录暂不可用时仍保留迁移后的记录。 |
| 备份窗口（1.6.9） | 未选中、选中多个或文件消失时明确提示；支持定位选中文件、双击/回车定位、独立打开备份目录及刷新。显示可读条目名和备份生成时间，删除后更新统计。删除仅处理所选备份，不再顺带轮换其他文件。 |
| GUI 弹窗 | 手动安装结果汇总到一个窗口，不按两端反复弹浏览器确认；摘要提供去重后的下载页入口。子对话框关闭后恢复父对话框的模态控制。 |
| GUI 设置布局 | 设置页支持滚动，“保存全部设置”固定可见；自定义来源正则输入与保存按钮分行，GitHub 也可以设置资产筛选。编辑同一来源保留适用确认与过滤。 |
| 后台任务 | 活动任务计数用于防止操作期间直接退出；回调异常恢复忙状态，失败检查不再显示空的成功摘要。界面日志持久化到操作日志。 |
| CLI 凭据 | Token 输入不回显，已有 Token 不作为输入默认值打印；代理菜单只显示地址与端口。 |
